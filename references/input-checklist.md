# OA 输入解析清单（input-checklist）

> **用途**：执行 Step 1（收集输入）与 Step 2（解析 OA 要素）时全文加载。按本清单逐项提取审查意见通知书与申请文件中的要素；要素缺失时参照文末"降级路径表"处理。
>
> **全文阅读要求**：v2 要求对申请文件**全文深度阅读**——权利要求书（区别特征来源）、说明书（发明内容/具体实施方式/实施例/附图描述，论证依据）与附图均须通读，不得只读权利要求书。

---

| 发明名称 | 通知书头部 | 与申请文件一致 |
| 申请人 | 通知书头部 | |
| 代理机构/案卷号 | 通知书头部 | 若有 |

|---|---|---|

| 发文日期 | 通知书头部 | |

## 三、表格勾选项（审查员结论性意见）

| 要素 | 位置 | 用途 |
|---|---|---|
| 第 6 项"审查的结论性意见" | 通知书表格 | 逐项勾选记录；区分**驳回条款缺陷**（三性、A26.3、A26.4、A33、客体等）与**非驳回形式缺陷**（撰写格式等）；据此定严重等级与答复优先级 |
| 第 7 项"审查员认为"（三选一） | 通知书表格 | ①可通过修改克服缺陷 ②有授权前景但存在缺陷 ③无授权前景、将被驳回——**直接决定答复策略基调**（可修改争辩 / 必须大改 / 考虑放弃或撤回） |

> **不兼容通知书情形（排除项）**：本 skill 以**电子申请系统（专利业务办理系统）下发的标准审查意见通知书**（含上述第 6/7/8 项表格结构）为解析对象。以下情形**不在支持范围**，识别到即提示用户另行处理，不套用本流程：
> - **纸件通知书**（无标准表格结构、勾选项缺失）；
> - **补正通知书/审查意见补正通知**（程序性补正为主，非创造性答复场景）；
> - **PCT 进入中国国家阶段通知书**（程序要素、期限规则与国内申请不同）。
> 如通知书为上述情形，输出提示并建议按对应程序处理，不得强行按创造性答复流程分析。

## 四、正文逐条审查意见（核心解析对象）

逐条提取，每条记录：

| 字段 | 说明 |
|---|---|
| 意见序号 | 正文编号 |
| 针对对象 | 具体权利要求号（如权利要求 1、3）或说明书某部分 |
| 审查员认定的事实 | 审查员认为权利要求公开了哪些内容、与对比文件如何对应 |
| 引用法条 | 具体条号（注意是否为现行版条号） |
| 引用的对比文件 | 文献号（如 D1、D2）、公开日、类型（现有技术/抵触申请）、引用方式（X/Y/A 类） |
| 公知常识认定 | 审查员是否以"公知常识"认定某特征 |
| 修改要求 | 审查员要求修改的具体内容（如有） |

> 提示：正文常出现"对比文件 X 公开了……"的逐特征对应分析，这是争辩分析的核心素材，逐条保留原文表述，不要改写审查员的技术认定。

## 五、申请文件要素

| 要素 | 说明 |
|---|---|
| 权利要求书全文 | 逐条提取，含从属权利要求引用关系；修改策略与超范围评估的基准 |
| 说明书 | 背景技术、发明内容（拟补入独权的特征来源）、具体实施方式与实施例（数值、参数、效果数据出处） |
| 附图清单 | 附图号与对应内容（注意：附图无文字记载一般不能单独作为修改依据） |

## 六、对比文件要素

| 要素 | 说明 |
|---|---|
| 全文 | 争辩分析建议获取全文（官方库链接可由公开号构造，见 `authoritative-sources.md`） |
| 关键段落 | 审查员引用的具体段落/附图标记需对照原文核实后再引用 |

## 六之二、上次答复材料（第 2 次及后续 OA 必需）

| 要素 | 说明 |
|---|---|
| 上次《意见陈述书》 | 确定上次争辩了哪些点、审查员本次接受了哪些 |
| 上次修改对照页/修改后权利要求文本 | 确定"已承诺范围"：上次已并入权利要求1的特征不得删除或扩大 |
| 缺失处理 | N≥2 时缺失即停止（材料完备性规则），无法确定已承诺范围不能安全答复 |

## 六之三、程序性要素识别（Step 2 强制核查，影响判断基准）

**作用**：三要素影响 A33 超范围判断基准、现有技术时间点、重复授权处理。识别依据：通知书、申请文件著录项、提交文件（如分案请求书、优先权声明、同日申请说明）。**识别结果必须写入案件要素解析表，并在初稿"答复策略说明"中单列"程序性要素"提示；无法从材料确定时列入《附件·答复辅助材料汇总·提交前复核清单》，不臆断。**

| 程序性要素 | 识别线索 | 识别后处理 |
|---|---|---|
| **分案申请** | 申请文件/通知书中"分案""母案"字样；著录项目录载有母案申请号；原申请号非本申请原始申请号 | A33 修改超范围判断基准 = **母案原始记载**（amendment-scope-checklist 中"原说明书和权利要求书"指母案）；修改依据出处须注明"母案说明书第×段/母案权利要求×"；分案修改不得引入超出母案记载范围的内容 |
| **要求优先权** | 著录项目录"优先权"栏有在先申请号与优先权日；申请人主张优先权 | 现有技术时间点以**优先权日**为准（优先权成立时）；对比文件公开日介于优先权日与本申请申请日之间的：若优先权成立按现有技术处理，若优先权不成立（如未在规定期限内提交在先申请文件副本、在先申请已撤回）则该期间公开文件不构成现有技术——答复中涉此情形须先核验优先权效力，无法核验的**不写入正文**，登记《附件·答复辅助材料汇总·待核实事项清单》 |
| **同日申请** | 著录项目录记载同日申请的实用新型/发明申请号；通知书中"同样的发明创造"（A9.1）意见 | 涉 A9.1 时答复须给出处理方案：修改本申请权利要求以区分、或放弃同日申请的实用新型（需申请人确认后提交放弃声明）；不得自行决定放弃 |
| 涉程序性要素的对比文件性质 | 对比文件公开日 vs 优先权日/申请日 | 抵触申请（申请日早于本申请、公开日晚于申请日）只能评新颖性不能评创造性；识别有误会直接影响创造性论证基础 |

> 说明：分案申请的 A33 基准与普通申请不同，**这是最容易出错的程序性盲区**——若材料可判断为分案，超范围核对清单（amendment-scope-checklist.md）全部以母案为基准执行。

## 七、材料缺口处理（材料不齐 = 停止，最高优先级）

**规则**：通知书、申请文件（权利要求书+说明书+附图）、审查员引用的全部对比文件，任一缺失或识别存疑 → 在 Step 1 停止流程，输出《材料缺口清单》，**不进入分析、不生成初稿**。理由：缺少材料时生成初稿必然以推测填充技术事实，违反真实性纪律，无继续必要性。**AI 不得自行降级处理**；仅当用户了解风险后仍明确要求继续时，按 SKILL.md Step 1 降级模式处理（正文零标记，转述论点登记《附件·答复辅助材料汇总·待核实事项清单》+《材料降级处理提示》，产出仅作工作底稿）。

| 情形 | 处理方式 |
|---|---|
| 缺 OA 通知书全文 | 停止，索要通知书 |
| 缺本申请权利要求书全文 | 停止；权利要求书是区别特征来源，缺失则无法确定区别特征与修改依据 |
| 缺本申请说明书全文或附图 | 停止；说明书（发明内容/具体实施方式/实施例/附图描述）是论证依据与修改出处，缺失则无法逐字引用与超范围评估 |
| 缺审查员引用的对比文件全文 | 停止；区别特征比对、结合启示判断、公知常识反击均依赖对比文件原文，缺失则论证无事实基础 |
| 扫描型 PDF 识别存疑 | 关键数字（申请号/法条条号/日期/公开号）识别不可靠时视为材料不完整，列入缺口清单，要求人工核对 |
| 用户要求材料不齐时继续 | 默认拒绝并说明风险；**用户了解风险后仍明确要求继续** → 降级模式：基于可用材料+通知书转述生成，**正文零标记**（不出现「待核实/基于转述」），转述论点登记《附件·答复辅助材料汇总·待核实事项清单》，初稿头部加《材料降级处理提示》，产出仅作工作底稿 |
| 材料齐备但 OA 含非创造性条款 | 不属缺口：仍以创造性为主完成答复，初稿"其他条款处理说明"逐条列出处理建议（见 SKILL.md Step 2） |
| OA 只有正文、无表格勾选项 | 不属缺口：按正文文本归类条款；第 6/7 项勾选情况未知，授权前景判断标注为**初步判断** |
