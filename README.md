# 发明专利OA助手（invention-patent-oa-assistant）

> 针对中国发明专利申请的审查意见通知书（OA）提供自动流转（无确认关卡）答复支持的 AI skill：从材料收集到《意见陈述书》初稿自动完成，默认一次跑完（材料规模超阈值时自动分段执行），产出完整的答复包初稿。

## 一、这是什么

针对中国**发明专利申请**的**审查意见通知书（OA）**提供**自动流转（无确认关卡）的答复支持**的 AI skill。重点覆盖创造性审查意见（专利法第 22 条第 3 款），同时扫描常规条款缺陷防止遗漏、识别程序性要素（分案/优先权/同日申请）。从材料收集到《意见陈述书》初稿自动完成，默认一次跑完（规模超阈值时自动分段执行，仍属自动流转）、零第三方依赖。

**适用范围**：仅限发明专利申请的审查阶段答复，不适用于实用新型；生物材料保藏、遗传资源、保密审查等条款不属扫描对象（见速查表"未覆盖条款说明"）。

## 二、核心能力特点

| 特点 | 说明 | 解决什么问题 |
|---|---|---|
| **自动流转（无确认关卡）** | 各步骤之间不询问、不等待确认，默认一次跑完；材料规模超阈值时自动分段执行（任务面板可见暂停点） | 传统流程中"每步都要人确认"的低效 |
| **材料完备性硬门槛** | 通知书/申请文件/对比文件缺一即停止，输出缺口清单，不硬生成 | 材料不全时 AI 靠"猜"填充技术事实，违反真实性 |
| **引用铁律** | 区别技术特征**逐字引用原文 + 附图标记**，禁止概括、改写、重构 | 区别特征表述失真导致答复不被采信 |
| **三步法显式论证** | 最接近现有技术 → 区别特征与实际解决的技术问题 → 显而易见性判断，逐特征深度论证 + 结合启示阻断 | 审查员最常见的"三步法"逻辑链，逐环回应 |
| **双轨策略（推荐 + 备选）** | 推荐策略（默认最小必要修改）+ 备选策略对比呈现；论证素材与策略解耦，切换无需重跑流程 | 代理人可在使用前从容取舍，不因选错策略返工 |
| **程序性要素识别** | 自动核查分案申请（A33 以母案为基准）/ 优先权（时间点）/ 同日申请（A9.1） | 程序性缺陷容易被忽略，影响答复有效性 |
| **正文零标记纪律** | 无法核实的内容**不写入正文**，统一登记到附件《答复辅助材料汇总》之"待核实事项清单" | 交付物正文干净，不含任何待确认残留 |
| **防编造纪律** | 不编造对比文件内容、段落号、法条原文、实施例数据；引用段落号前先程序化锚定 | AI 幻觉是法律文书的最大风险 |
| **11 类论证模式库** | 数值临界/时序依赖/跨领域障碍/技术偏见/预料不到效果等实战论证手法 | 面对不同类型的审查意见有对应打法 |
| **固定交付标准** | 3 docx + 1 md 四个文件：意见陈述书、权利要求书替换页、权利要求修改对照页、附件汇总 | 交付物结构统一，附件为辅助材料（使用后删除） |
| **三处一致性机检** | 意见陈述书"修改说明"、修改对照页、替换页三者逐条比对，不一致即 FAIL | 三份文件同一次生成，漏改或改错时文书仍"看起来完整"，肉眼极难发现 |
| **高风险修改拦截** | 对照页出现 🔴 级高风险修改（无出处/仅附图图形/引入新主题）即 FAIL | "高风险不得列入修改方案"此前全靠自觉，无兜底 |
| **端到端集成测试** | 产物**由模板派生**后跑全套机检，模板与脚本的规则冲突在改完时就 FAIL | 单脚本单元测试测不到"模板↔脚本"接缝，缺陷只能等实跑撞见 |
| **进度可见的任务清单** | Step 1 通过后立即创建 15 条任务、输出完整清单概览，随后逐条划掉 | 长流程中用户随时知道进行到哪一步 |

## 三、工作流程（11 步概览）

```
Step 1  收集材料 + 完备性检查（缺材料即停止）
Step 2  解析要素 + 常规条款扫描 + 程序性要素识别
Step 3  深度阅读（本申请 / 对比文件 / 审查意见）
Step 4  确定区别技术特征（引用铁律 + 自证核查）
Step 5  特征解构与实质比对（防割裂特征审查）
Step 6  策略双轨呈现（推荐 + 备选，决策权归用户）
Step 7  逐特征深度论证（结合启示阻断）
Step 8  生成权利要求修改对照页（超范围风险标注）
Step 9  撰写《意见陈述书》初稿（必备要素硬清单）
Step 10 质量自检（机检项 + 人检项）
Step 11 交付：3 docx + 1 md（逐件生成、逐件落盘）
```

**进度可见**：Step 1 完备性判定通过后**立即**一次性创建 15 条任务（Step 1–10 各一条，Step 11 按交付物拆为 5 条），并在回复中输出完整清单概览；随后每完成一步即在任务面板逐条划掉，不批量补标。

## 四、怎么用

在对话中发送以下任一触发语，并附上必需材料：

- "帮我答复这个审查意见"
- "分析一下这份OA"
- "这个驳回条款怎么争辩"
- "帮我写意见陈述书"
- "帮我修改权利要求答复审查意见"

**必需材料（缺一即停止，会提示补齐）**：
1. 审查意见通知书全文
2. 申请文件：权利要求书 + 说明书
3. 审查员引用的对比文件全文
4. 第 2 次及后续 OA 还需：上次《意见陈述书》+ 上次《权利要求修改对照页》（用于确定"已承诺范围"）

**可选项（缺失不阻塞、不弹窗）**：附图。本 skill 全程基于文本工作、不解析图像内容——特征比对、结合启示判断、超范围核对一律以权利要求书与说明书的**文字记载**为准，结构理解依赖说明书「附图说明」章节与附图标记一览表。

## 五、交付物（固定标准：3 docx + 1 md）

| 文件 | 格式 | 说明 |
|---|---|---|
| 意见陈述书初稿 | .docx | 答复正文（含答复策略说明 + 三步法论证 + 修改说明） |
| 权利要求书替换页 | .docx | 修改后权利要求书完整全文、无修订标记 |
| 权利要求修改对照页 | .docx | 原→改→依据→超范围风险，内部记录 |
| 附件·答复辅助材料汇总 | .md | 待核实事项清单 + 引用锚定表 + 复核清单（辅助材料，使用后删除） |

## 七、核心规则速览

| 规则 | 说明 |
|---|---|
| 材料完备性 | 通知书/申请文件/对比文件缺一 → **停止**，输出缺口清单，不硬生成；（**附图为可选项**，缺失不阻塞） |
| 自动流转 | 材料齐备后各步骤不询问、不等待确认，默认一次交付完整初稿；规模超阈值时自动分段执行 |
| 进度可见 | Step 1 通过后一次性创建 15 条任务并输出清单概览，每完成一步立即划掉，不批量补标 |
| 引用铁律 | 区别特征逐字引用原文 + 附图标记，禁止概括改写 |
| 真实性 | 不编造对比文件内容/段落号/法条原文/实施例数据 |
| 零标记 | 正文不含「待核实/待补」等标记与占位指令，统一登记附件清单 |
| 条号 | 专利法 2020 / 实施细则 2023 / 审查指南 2023（现行版） |
| 机检工具 | **12 个**纯标准库检查脚本（材料/引用/字数/链条/超范围/三处一致性/条号/自足性/术语/AI痕迹/零标记/交付物），统一退出码约定（0 通过 / 1 不通过 / 2 用法错误） |
| 回归测试 | `run_regression_tests.py` 内置 **65 个用例**（含 11 个端到端用例：产物由模板派生后跑全套机检），修改本 skill 后运行确认行为未退化 |
| docx 生成 | 脚本纯 Python 标准库实现，零第三方依赖（可选使用） |

## 八、免责声明

- **数据隐私**：所有处理（含全部机检脚本）均在你本地完成，**不联网、不上传、不收集**任何输入材料与生成内容——你的专利申请文件不会离开你的设备。
- 本技能输出为**分析辅助与初稿**，不构成法律意见；实际使用前须由执业代理人复核技术事实、法条引用、修改文本与答复策略。
- 法条以现行有效版本为准（专利法 2020 修正、实施细则 2023 修订、审查指南 2023）；引用前请核取官方文本。法条/细则修订后，内置条号映射表需同步更新。
- 本技能仅适用于中国发明专利申请的审查阶段答复，不适用于实用新型、复审、无效宣告、PCT 国际阶段等程序。

## 九、版本记录

### v2.1.0（2026-09-03）

**新增能力**

- **端到端集成测试**：产物由 `opinion-letter-template.md` **派生**（而非手写样例）后跑全套机检，模板与脚本的规则冲突在改完时就 FAIL。含 11 个端到端用例，已用变异测试验证有效性。
- 新增脚本 `check_amended_claims.py`（三处一致性 + 多项独权重叠提示）、`check_amendment_risk.py`（🔴 级超范围拦截）、`_exempt.py`（豁免规则公共模块，改豁免只改这一处）。
- 任务清单机制强化为四条硬约束：15 条任务、创建后立即展示全貌、逐个划掉、交付阶段逐条可见。

**规则修订**

- **附图由硬性必填改为可选项**：本 skill 不解析图像内容，缺失不再阻塞、不再弹窗等待确认。保留无附图时的三条执行纪律（论断以文字记载为准不作推定；审查意见"由图×可以确定……"类认定不正面反驳、只请求说明依据并登记待核实清单；材料清单记录一句"结构理解以文字化附图信息为准"）。
- 模板一律不使用 `【】` 标记指令（会被零标记机检判为占位符残留），改以行尾括号注记或 `〔…〕` 表示。
- 新增 Step 6 定案后的**区别特征复核回路**（`inventive-step-analysis.md` 3.5：Step 9 论证对象是修改后的权1，比对基准须与之对齐，未复核不得进入 Step 7）与**回归候选处理**（2.6：Step 5 推翻"已公开"认定后的回归路径，回归后仍须过自证核查）。
- `check_citations.py` 阈值 0.50 → 0.60 并增加论述性表述豁免，误报显著下降（实测一份合格初稿由 19 处降至 6 处）。

**修复**

- 附件与过程文件的豁免范围过窄：此前只豁免"待核实类标记"，导致附件中模板要求写出的"Step N 产出""（逐字引用）"被误判为残留。现为前缀全豁免。
- 模板缺陷 7 处：3 处 `【】` 占位符、"Step 2"框架泄漏、章节编号重复（两个"二、"）、括号内含"写入"触发执行指令规则等。
- 回归用例期望文本过宽导致**长期假通过**：期望"疑似改写引用"会命中结果行"**未检出**疑似改写引用"，该用例从未真正验证过 WARN 检出能力。已改用精确锚点。

**验证**：回归 65 个用例全部通过；激光雷达案（202210955344.2）真实产物全套机检通过；新增能力均通过变异测试。
